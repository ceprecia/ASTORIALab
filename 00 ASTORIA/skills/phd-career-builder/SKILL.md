# PhD Career Builder

Set up support around the user's program, career goals and academic working preferences.

## User Q&A

Answers belong in the chosen existing MOC, never in this skill. Read its current
answers first; `TK` means not yet supplied, not a request to repeat the interview.

- Program, cohort and sources: chosen MOC; otherwise TK.
- Milestones, progress and workload: chosen MOC; otherwise TK.
- Mentoring and meetings: chosen MOC and current `me.md`; otherwise TK.
- Career direction and networking: chosen MOC; otherwise TK.
- Opportunity profile and eligibility: chosen MOC; otherwise TK.
- Speaking practice: chosen MOC; otherwise TK.
- Posters and slides: chosen MOC; otherwise TK.
- Collaboration and communication: chosen MOC and `me.md`; otherwise TK.
- Watch and reminder operations: chosen MOC; otherwise TK.

## Purpose

Own initial setup and bounded refresh of the local settings used by PhD
Companion and its relevant specialists. Turn the user's program, career and
working preferences into enough specific context for useful assignments. Reuse
the existing owner and sources. Leave actual advising, policy reconciliation,
screening, coaching, artifact production and scheduling to their owners.

## Inputs

- The requested setup or refresh, current conversation and `me.md`.
- Setup answers and any already approved save scope supplied by setup-my-vault
  or the invoking owner; reuse them rather than running a second interview.
- The user's chosen existing MOC, applicable project instructions and its relevant
  sections. Locate an existing owner from the request and `me.md` before asking.
- Supplied program/cohort documents, official links and completion evidence.
  Missing documents can remain explicit gaps.

## Steps

1. Read the existing owner's orientation and relevant sections following `me.md`.
   Locate existing configuration and answers before asking anything. For a refresh,
   change only the requested settings and facts affected by current evidence.
2. Assemble a preliminary profile from those sources and the conversation. Mark
   each consequential fact as official, user-confirmed or unknown, with its source
   and applicable date/cohort where known. A handbook's publication year alone
   does not establish that it governs this cohort. Surface conflicting facts.
3. Select useful questions from the groups below. Reuse supplied answers and
   ask only unanswered or conflicting items that affect the requested supports.
   Normally start with one to three relevant groups and at most six answerable
   questions, then follow the user's replies. If the user asks for the whole
   interview, provide a substantial grouped set covering the relevant system.
   Do not make every group mandatory. A user can skip, defer or answer unknown;
   continue work that does not depend on the missing answer. Request links or
   existing documents instead of asking the user to retype discoverable details.

   > [!question] Ask on first run
   > **Program, cohort and sources:** Which institution, department/program, track, degree and entering cohort apply? Which existing MOC should own the support settings? Can you point to the official program page, governing handbook/catalog and any later amendments, or to an existing note that links them? If applicability is uncertain, which program contact or written guidance can clarify it?

   > [!question] Ask on first run
   > **Milestones, progress and workload:** What stage are you at, and which courses, exams, proposal, committee and dissertation steps are completed, underway or uncertain? Where is the evidence, including approved exceptions or extensions? Which dates are official deadlines and which are your targets? What workload, available time and fixed scheduling commitments affect a realistic completion window? Availability is sufficient; there is no need to explain private reasons behind it.

   > [!question] Ask on first run
   > **Mentoring and meetings:** Who fills the advisor, committee, mentor and sponsor roles, and what support do you need from each? What decisions or difficult conversations are approaching, and what would a useful outcome look like? What meeting types, cadence and preparation/debrief format help? Which existing agendas, notes or supplied transcripts should the meeting advisor use to identify decisions, action owners and follow-ups?

   > [!question] Ask on first run
   > **Career direction and networking:** Which academic or other career paths are you exploring, and which criteria matter most when comparing them? What skills, experience or relationships would help, and what evidence already exists in your CV or project records? Which mentors, groups, conferences or supplied attendee lists matter now? What should a useful introduction, conversation or follow-up accomplish, and what constraints should shape it?

   > [!question] Ask on first run
   > **Opportunity profile and eligibility:** Which opportunity types matter: funding, travel awards, training, conferences, internships, fellowships, postdocs or jobs? What fields, locations, institutions, funding options, resources and start windows fit, and which are requirements versus preferences? Which eligibility facts are confirmed, with what source, and which should remain unknown until a specific notice requires them? Are there exact sponsors, program pages or existing lists to start from or exclude?

   > [!question] Ask on first run
   > **Speaking practice:** What audience, setting, time limit, main takeaway and Q&A format should practice target? Which supplied talk, script, recording or transcript can the coach use, and what feedback on clarity, pacing, delivery or difficult questions would help most? Are there particular speakers or coaches, with example links and specific techniques you want to practice or avoid? What practice format feels useful and manageable?

   > [!question] Ask on first run
   > **Posters and slides:** Is the next deliverable a poster, slide deck or both, for which event, audience, dimensions, time limit and deadline? Which approved content, figures, existing deck or institutional template should it use? What tool, editable format, export format and visual requirements matter? Which parts are already settled, and should support focus on structure, layout, artifact production or rehearsal?

   > [!question] Ask on first run
   > **Collaboration and communication:** Beyond `me.md`, what tone, detail, feedback and check-in format helps? Which current project chats and roles already work well, and when would a dedicated specialist chat versus support here help? What relevant communication or information-sharing preferences have not already been supplied?

   > [!question] Ask on first run
   > **Watch and reminder operations:** Should opportunity watches and deadline reminders stay disabled or be configured? For a configured watch, what cadence/time zone, source/profile scope, eligibility states and material changes should produce a notice? Which deadline thresholds and repeat limits help, where should notices and compact item state live, and where should access or delivery failures be reported? Has an actual scheduler/delivery mechanism been selected, or are these preferences only? Scheduling remains separate from this interview.

4. For initial setup or a substantive refresh, give one compact readback of proposed
   settings, reused answers, evidence conflicts, explicit gaps and exact existing
   MOC sections to update. Explain what can proceed and what needs an answer.
   Ask for confirmation or corrections once before saving unless that exact
   update is already authorized; no per-group approval checkpoints. A correction
   updates the proposal without restarting the interview. Apply an explicit
   bounded preference correction directly within its authorized field.
   An approved setup-my-vault readback supplies this confirmation for the same
   fields and destination; do not require another builder-specific sign-off.
5. Save the approved compact configuration only in the selected existing owner
   sections. Reuse existing fields and wording where possible. Add only needed
   subsections within the MOC's architecture; preserve surrounding prose,
   headings, historical entries and unrelated decisions. Store the following only
   where useful, rather than creating every field automatically:
   - Program/cohort, governing source references and unresolved applicability.
   - Milestone status and completion-evidence pointers, with explicit uncertainty.
   - People by relevant role, current goals and constraints.
   - Requested specialist preferences, such as meeting preparation, speaking
     practice, presentation formats or networking goals, with useful source paths.
   - Opportunity profile: eligibility facts with evidence status and preferences.
   - Communication preferences not already supplied by `me.md`.
   - Operations: disabled/configured state, cadence/time zone, profile and source
     scope, notification/reminder thresholds, chosen destination and compact
     per-item state location. Record scheduling as unconfigured unless the user
     separately selected an actual scheduler.
6. Return the saved owner/section, approved scope, unresolved fields and relevant
   next skill to the invoking owner, normally PhD Companion. Include the exact
   MOC/profile and task-source paths in a specialist handoff; a general instruction
   to find personal context is insufficient. If the owner or save authorization is
   absent, return the unsaved proposal in the current task's requested response form or under the recipient's existing reporting policy. Continue
   independent requested work.

## Outputs

Save one bounded configuration update in the existing MOC only within the
authorized scope. Keep interview dialogue, alternatives and full transcripts
outside that update. Return requested unsaved material in the current task's requested response form or under the recipient's existing reporting policy.
Record only useful answers for requested supports and omit empty questionnaire fields.
Describe partial configuration accurately; no personalized skill variant,
duplicate profile, dashboard, new MOC or second setup note is produced.

## Boundaries

- Configuration records preferences and facts; it does not create jobs, send
  messages, enroll, apply, submit or establish completion of a requirement.
- Do not infer eligibility, a deadline, policy applicability, advisor intent or
  an exception's approval from an incomplete note. Preserve its evidence status.
- Keep reusable instructions person-neutral and profile values in the existing
  owner. `me.md` remains the personal briefing rather than a copied biography.
- Missing optional configuration does not block unrelated mentoring or support.

## Handoffs

- Return session decisions to the invoking owner, normally PhD Companion.
- Use phd-program-navigator for current cohort rules and evidence reconciliation.
- Use phd-opportunity-scout for exact opportunities, screening and watch checks.
- Pass the relevant owner settings to phd-meeting-advisor, public-speaking-coach,
  research-presentation-builder, phd-networking-advisor or phd-career-advisor for
  their requested jobs. Reuse research-cv-builder and research-grant-advisor for
  their canonical document and selected-application services.
- Actual recurring-task setup is a separate user-selected scheduling action.

## Checks

- Answers already supplied were reused; missing facts are visible.
- Each proposed stored field has an existing owner and a current purpose.
- Requested specialist support has concrete audience, goal, constraints and input
  paths where supplied; unsupported details remain visible gaps.
- Source authority, cohort applicability and completion evidence remain distinct.
- The saved change matches the approved readback and preserves existing material.
- Configured reminder preferences are never reported as an active scheduled job.
