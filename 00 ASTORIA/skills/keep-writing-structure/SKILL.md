# Keep Writing Structure

Preserve the chosen structure and identify what it still needs to contain.

## Purpose

Own template fidelity, section order, required functions and structural limits.
Compare the current document with the user's selected model and applicable
requirements. Diagnose structural drift separately from prose quality,
scientific validity and detailed reporting completeness.

## Inputs

Read the [writing contract](../writing-coordinator/references/writing_contract.md).
Load the brief, relevant MOC, recipient-supplied writing guidance, current document and
exact selected template or example. Obtain requirement sources, versions and
limits from the domain or application owner. Identify frozen text, required
headings and permitted structural flexibility.

## Steps

1. Distinguish three inputs: mandatory current requirements, the user's chosen
   organization and examples that illustrate style. Record a material conflict
   instead of silently treating an example as policy.
2. Build a small structural map: section name, required function, ordering
   dependency, size or format limit and source. Use only applicable constraints.
3. Compare actual headings and content with that map. Inspect the text under
   a heading; a label such as Procedure does not establish that procedures are
   described.
4. Detect missing, duplicated or relocated functions, unexplained heading
   changes, disproportionate sections and content that answers a different
   section's question.
5. Check the selected repeated pattern across units. If the user chose an
   aim-by-aim Overview, Purpose, Procedure, Data Analysis Plan and Alternative
   Outcomes pattern, preserve it rather than imposing shared methods or IMRaD.
6. Separate structural findings from missing science. A methods section may
   occupy the right place while lacking parameters; keep the placement finding
   here and return the detail gap to the substantive owner.
7. Propose the minimum repair with exact source and destination locations.
   Move or edit content only within the assigned scope. Preserve frozen
   wording and required terminology during authorized repairs.
8. Recheck affected cross-references, section numbering and declared limits.
   If a limit requires rendered pagination or native document inspection,
   obtain that evidence through the document capability; text length alone
   cannot establish page compliance.

## Outputs

A concise structure map or findings table with location, governing constraint,
observed drift and concrete repair. State whether only text structure or also
the rendered artifact was checked. Return an annotated outline when that is
more useful than prose.

## Boundaries

- Do not equate template fidelity with sufficient substance or argument.
- Do not replace the user's selected structure merely because another is common.
- Verify unstable external requirements through current official sources.
- Do not silently cut substantive qualifications to meet a length target.
- Return review findings in the requested deliverable or according to the recipient's configured reporting policy. Create a separate saved report only when requested or configured and authorized.

## Handoffs

Return through writing-coordinator. organize-writing-project tracks section
readiness; check-research-reporting audits guideline disclosures;
check-writing-substance checks operational specifics; a named paragraph-method review through check-writing-cerl is available only when the recipient selects it. Other reasoning review follows the document's purpose. Requirement conflicts return to the owning specialist
through [cross-system handoffs](../writing-coordinator/references/cross_system_handoff.md).

## Checks

- Every finding names a selected or applicable requirement.
- Required functions are checked against content, not heading presence alone.
- Proposed moves preserve logical dependencies and frozen material.
- All claimed layout checks identify the inspected artifact.
