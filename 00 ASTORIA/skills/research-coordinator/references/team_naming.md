# Shared specialist chat naming

This is the single prefix and ID registry for research, career, engineering and shared writing project chats. Read
it before proposing or assigning a chat name. Prefixes identify work lanes;
they are not inquiry-part numbers, scientific stages or skill names.

## Contents

- [Fixed prefixes](#fixed-prefixes)
- [Titles and stable identity](#titles-and-stable-identity)
- [Fixed writing role labels](#fixed-writing-role-labels)

## Fixed prefixes

| Prefix | Work lane |
| --- | --- |
| RS | Research Companion, the project team lead |
| PD | PhD Companion and career, program, mentoring or professional-development support |
| LT | Literature, field scouting and first-principles research |
| DS | Question development, critique, hypotheses, design and power |
| BH | Behavioral and cognitive-data analysis |
| FM | Functional MRI preprocessing, QC and analysis |
| AN | Other modalities and cross-modal analysis |
| WR | Shared writing assistance: planning, evidence, content writers, review and integration |
| EN | Engineering technical specialists, including mechanisms, circuits, wiring, firmware and testing |
| DC | Protocols, progress capture, handoff and other documentation |

Use the existing appropriate prefix. Do not invent aliases, derive prefixes
from skill names or add a prefix for every method, stage or dataset. A genuine
uncovered lane is a proposed registry change, not a new ad hoc code.

## Titles and stable identity

Use `PREFIX-NN Role - Focus`, for example `WR-05 Methods Writer - instrument procedure`. Omit a
redundant focus when the role is already unambiguous. `RS-00 Companion` is the
default for a research lead when 00 is unassigned; `PD-00 Companion` is the PhD
lead equivalent. `WR-00 Writing Companion` and `EN-00 Engineering Companion` follow the same rule for standalone leads. A borrowed writing service stays within its existing lead rather than adding another 00 chat. Preserve an existing lead identity. If another team already
occupies 00, give a new lead the next project-wide number instead. The
Coordinator stays inside that lead chat; it receives no
separate chat or ID. Several chats may use the same skill.

- Numbers are unique across the current Codex project, including other lanes
  and retained archived team chats. Use 00 for a new lead only when
  available. For a new worker use the next unused number above the highest
  assigned project number.
  Pad to at least two digits; 99 is followed by 100. Do not recycle gaps.
- Check the live project chat inventory and any authorized team mapping at
  the verified continuity location before allocation. Reuse a suitable authorized chat and retain its
  ID and established title. Do not rename legacy chats as part of allocation.
- The original project lead coordinator is the one allocation owner for the
  scoped team. Borrowing/lending coordinators request reservations from it and
  never allocate independently. A standalone lead owns its team allocation.
  Include already reserved or pending creations as occupied, and allocate new
  IDs before dispatch so parallel workers cannot select the same number. Never derive IDs from script stages,
  derivative folders, participant IDs or inquiry-part numbers.
- Keep a chat's focus stable. Do not renumber it merely because the workstream
  moves between stages. Use a short study, manuscript, participant or analysis
  qualifier when it distinguishes concurrent assignments.
- Bind all selected workers to the current companion chat's verified Codex
  project, unless the user selected another destination. Source-file locations,
  project names in notes and similar chat titles do not establish that binding.
  If binding is unavailable, leave persistent chat ID allocation pending rather
  than guessing a project. Internal work follows the applicable execution
  contract; naming alone does not establish a dispatch workflow.
- When a continuity update is authorized, keep only the role, skill, chat or
  host ID, scope, owned outputs and state needed to resume. Use the verified
  location selected for the task or established by the applicable project
  continuity policy. Prefixes and rules stay here, not copied
  into each project. Creating or naming a chat does not authorize scientific
  execution, saving, external contact or publication beyond the current scope.

## Fixed writing role labels

Use the WR prefix with the following stable role labels. These labels map to skills;
the number is the project-wide chat identity, not a role number. For example,
`WR-12 Bibliographer - literature revision` and `WR-13 Structure Keeper - report outline` use the
same prefix convention. Do not invent a new prefix, abbreviation or role label on
each kickoff. A new catalog role requires one deliberate registry update here.

| Fixed role label | Canonical skill |
| --- | --- |
| Writing Companion | writing-companion |
| Organizer | organize-writing-project |
| Argument Planner | plan-writing-argument |
| Evidence Specialist | develop-writing-evidence |
| Structure Keeper | keep-writing-structure |
| Bibliographer | verify-writing-citations |
| Substance Reviewer | check-writing-substance |
| Reasoning Reviewer | check-writing-cerl |
| Reporting Reviewer | check-research-reporting |
| Domain Translator | translate-specialist-methods |
| Integration Editor | integrate-writing |
| Title Writer | write-title |
| Abstract Writer | write-abstract |
| Introduction Writer | write-introduction |
| Methods Writer | write-methods |
| Results Writer | write-results |
| Discussion Writer | write-discussion |
| Conclusion Writer | write-conclusion |
| Figure/Table Writer | write-figure-table-text |
| Figure/Table Reviewer | review-figures-tables |
| Section Writer | write-section |

writing-coordinator is internal and never gets a separate persistent chat.
The role list is a catalog, not a compulsory roster or a maximum team size.
Several Methods Writers can have distinct focuses and IDs. An application
section uses its content-specific writer or Section Writer with the exact
selected section title in the focus; the Organizer keeps section status.

Borrowed domain workers keep their existing prefix/identity, such as FM for an
fMRI specialist or EN for a circuit specialist; do not relabel them WR merely
because they supply methods detail. For new engineering chats use EN plus the
specialist's canonical role, such as Circuit Designer or Mechanism Designer,
with the exact component/interface as focus. Existing authorized legacy names
are preserved. Never allocate numbers from this example table.
