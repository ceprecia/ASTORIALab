# Research team scenarios

Bounded examples for interpreting the execution contract. They are generic
rehearsals, not scientific decisions, current project facts or evidence that
native dispatch or analysis has occurred. Names and numbers come only from
`./team_naming.md`; these examples do not allocate IDs.

## Data schema and analysis workstreams

**Request:** Inspect a supplied table schema and review an already approved analysis specification. Keep records unchanged and do not fit a model.

- Research Companion retains the question and synthesis; Coordinator verifies the relevant routes and selected skills.
- One worker checks field definitions, units and missing-value encodings. Another checks the supplied analysis specification against those definitions. Each receives its full instructions and the same source revision.
- Reuse suitable authorized workers and current project binding. If dedicated chats are unavailable, use bounded internal assignments with the same limits.
- Collect the verified schema facts and specification review. Launching workers does not authorize data conversion or model fitting.

## Multiple writers with literature support

**Request:** Draft Methods and a bounded Introduction passage in chat under the
supplied scientific frame. Find support for one unresolved literature claim.

- Assign write-methods and write-introduction through shared writing-coordinator. Several workers may use one content-specific skill for disjoint sections. Provide the same central claim/status, frame/version, terminology, selected structure, MOC writing guidance and claim limits, plus each section's relevant evidence.
- The explicit request authorizes these chat drafts. Do not insert a general roadmap approval or save step. Keep an unresolved contribution explicitly provisional; ask only about a scientific choice required to make an affected claim, without blocking a requested provisional scaffold.
- A literature worker handles only the unresolved claim. Continue supported text; mark the dependent claim conditional or omit it until evidence arrives. Do not invent a citation or turn the literature detour into project restart.
- Collect the actual drafts and literature result. One integration writer owns the canonical manuscript if later file integration is authorized. Do not create per-worker files by default.

## A changed data contract

**Change:** A source table's measurement unit is corrected while its identifiers and unrelated documentation remain valid.

- Send the corrected field definition and source revision to the producing owner and consumers.
- Identify calculations and interpretations that depend on the unit before requesting further work. Preserve unaffected records and checks.
- Hold dependent conclusions when the conversion or scientific meaning is unresolved. Do not relabel every artifact obsolete or change source data automatically.

## Archived manuscript replay

**Request:** Reconstruct which supplied archived results support a specified
manuscript correction. Historical notes disagree with the current instruction.

- Use the current instruction and supplied source artifacts; treat historical notes as dated context. Do not infer present project status or personal facts from the archive.
- Assign bounded source/result reconciliation and writing scopes under one stated current frame. Surface the conflict rather than adopting a historic claim.
- Return supported correction text and explicit evidence gaps. No scientific rerun, new interpretation, file saving or external submission follows solely from archival replay.

## Creation scope and host state

**Request:** Start the proposed current-project team for the named review and
chat drafts; later follow-ups correct a source citation in the same scope.

- The explicit scoped launch already authorizes creation, kickoff and those follow-ups. Reuse suitable authorized chats; verify current project binding and actual returned IDs rather than choosing a project from source paths.
- Retained archived IDs remain occupied under the naming registry. Keep assigned names stable through stage changes.
- A returned queued/pending creation is tracked as pending, then inspected through status/read tools. Collect requested outputs before claiming completion. Workers need not send unauthorized cross-chat replies.
- A later request for scientific execution, saving or external action is governed by its own current authorization and owning skill requirements.

## Fallback and compaction

**Condition:** Dedicated chats are declined or binding is unavailable; one
specialist question remains.

- Spawn one internal worker with its exact skill and bounded assignment; do not replace the specialist with an unsupported generic answer.
- If worker tools are also unavailable, or the user forbids all delegation, disclose sequential loaded-skill work and execute that workflow within scope.
- After context loss, the lead reloads its pair and current team context. A worker reloads AGENTS/briefing, its own full skill/guides, current assignment and sources. It does not load a second companion/Coordinator pair.
- Ordinary mentoring invoked through PhD Companion remains caller-owned under its existing bounded coordination contract; it does not trigger this research-team default.

## Shared support without automatic saves

**Request:** Convert established accepted steps into a protocol, then separately
capture completed work under the chosen capture preference.

- Discover the selected helpers through the generated Skill Map Capture and Writing Helpers group. Use their canonical skills, without copied folders or a second helper catalog.
- Preserve Write Protocol's existing overview selection, detailed review and publication rules. A completed worker result alone does not authorize a protocol insertion.
- Use the selected capture helper for the requested log. Record useful team IDs and state only when authorized, at the verified location selected for the task or established by the applicable project continuity policy. Do not create a team registry, new hub or automatic progress file.

## Methods writing across domain owners

**Request:** Write a Methods account from a verified laboratory processing record or data-import audit.

- Keep the original engineering/research companion as return owner. The shared writing coordinator asks its existing domain coordinator for exact specialist records rather than spawning a competing technical team.
- A translator preserves source revision, values/units, actual procedures, outputs and limitations. Planned, installed/executed, measured/reviewed and accepted remain distinct; absent settings stay unknown.
- The content writer drafts from that record and the common writing brief. The technical specialist checks fidelity; citation, substance, structure and argument-reasoning reviewers keep separate findings on the stable draft. One integration writer applies corrections to the canonical document.
- A writing request does not authorize a circuit change, new analysis, preprocessing rerun, image-QC acceptance or publication. Scoped authorized follow-ups reuse worker IDs and the fixed naming registry.
