# Folder Janitor Worked Examples

These fictional cases illustrate decisions, not a recommended taxonomy. Paths
are relative to an example vault. Resolve actual roots, collections, intake and
protected locations from the recipient's instructions. Read only relevant cases.

MOCs provide navigation and working context. A Project or Area root holds its
MOC and one AGENTS.md. Working content lives in its local files/ folder or a
documented external workspace. Reusable references stay in independent
Resources collections. Use approved destinations and respect any
established operational layout. Report missing entries without creating them.
Operational project layouts and chronological records retain their functions.
A coherent deep package can already be organized. Unlinked files are not deleted
merely because no note currently points to them.

Mechanical repairs change active path targets in links, embeds, MOCs, AGENTS.md,
specifications, configuration and scripts. Preserve labels, embed markers,
heading and block anchors, surrounding prose, scientific content, headings,
decisions and log narratives. A code fence does not make an active path historical.
A short link that still resolves to the same file may need no edit. These cases
do not authorize new MOCs, bridges, indexes or explanatory sections.

## 1. A translation with several source formats

**Request:** file a translation draft with its source material.
The recipient identifies an existing `Resources/translation_project/` collection.
Intake contains `translated_leaflet.md`, `source_leaflet.pdf`, a terminology CSV
and cropped illustrations. The draft names the PDF page and both crops.

Move these related files into the verified collection, retaining useful filenames.
Repair source links and illustration embeds in the same operation. Preserve page
anchors, crop choices and the translation. Do not create separate file-type pools
or one folder per document. The project MOC links the collection without copying it.

## 2. A recording with an established session owner

**Request:** place a soundscape recording and its transcript.
The transcript names an existing collection and matching session code. A general
note also links the recording; backlink count does not establish stronger ownership.

Keep the recording, transcript and supplied timing file with that session. Retain
session filenames and time references. Repair incoming links from both notes.
Do not merge sessions, infer missing facts or invent a new subject hierarchy.

## 3. Public event materials in an Area

**Request:** tidy the ongoing community-events Area.
`Areas/Community Events/` contains its MOC, AGENTS.md, a venue map, a volunteer
briefing and an earlier season's poster. The associated recipient-selected event
collection already distinguishes events by season.

Keep the MOC and AGENTS.md at the Area root. Place each supporting file under
its existing files/ with its known event, preserving season distinctions. Repair targets without rewriting the
Area's responsibilities or timeline. An unidentified poster remains unresolved.

## 4. A committee packet and a missing bridge

**Request:** organize a standards committee's reference packet.
Its Area has a populated MOC and supporting documents but no AGENTS.md. The
recipient confirms an existing files/ folder for the committee's documents.

File the documents and repair authorized MOC targets. Return the missing Area
instructions to Bridge Maker; filing does not authorize a bridge or parallel hub.
Preserve ballot wording and provenance. Do not search unrelated collections for
context merely because an instruction file is missing.

## 5. A shared color reference

**Request:** file a color-accessibility reference used by a map and a brochure.
An existing reference collection owns its explanatory note, palette file
and cited source. Both projects should link to that one canonical home.

Repair both incoming references. Preserve palette versions and source citations.
Do not duplicate the material into each project, choose its owner by link count
or overwrite a scientific variant.

## 6. A single held document

**Request:** file loose exhibition documents.
A collaborator is annotating `Resources/catalogue/catalogue_proof.pdf` at its
current path. The recipient holds that single document until comments return.
Independent illustrations have verified destinations under the current request.

Leave the proof and its links in place; file the independent items. Report the
proof as deferred and do not create an unused future destination. After the hold
is released, repair all active incoming paths in its authorized move. Filing does
not publish the document or approve its contents.

## 7. Operational research files keep their layout

**Request:** tidy loose background material for an estuary observation project.
The project owns `scripts/summarize_counts.py`, source observations and derivative
tables. Its script uses relative inputs. A loose field guide has a verified home
in the recipient's supporting-content collection.

File the reusable guide with its reference owner and repair its links. Keep
scripts, data and outputs in their established operational layout. Preserve
scientific variants, parameters and data-use conditions. Do not rerun analyses or
claim scientific validation from filing.

## 8. A chronological record points to a moved image

**Request:** file an illustration referenced by a dated capture.
The capture retains its date and configured Calendar location. Repair only an
active embed target when the record's instructions permit it; preserve the dated
narrative and quoted historical paths.

If the record is protected from edits, defer the affected move or return its exact
dependency to the owner. Do not leave a broken reference or relocate the capture
into the illustration's subject collection.

## 9. Unclear ownership without configured intake

**Request:** organize a labeled agenda and two unlabeled scans.
The agenda has a verified event owner. No evidence establishes the scans' owner,
and this vault has no configured intake location.

File the agenda under the existing request. Leave the scans where they are and
ask for their destination once. Do not guess their topic, read excluded folders
for clues, create a catch-all folder or use a human-owned inbox for agent output.
Report unresolved items without deleting them.

## 10. A deep delivery is already coherent

**Request:** review whether a map-tile delivery needs tidying.
The supplier's package contains a manifest, license, coordinate metadata and tiles
nested by zoom level and grid position. Its manifest relies on that structure;
repeated tile basenames refer to different positions.

Keep the package intact. Depth alone is not disorganization. An authorized later
relocation moves it as one unit and repairs external references and necessary path
prefixes. Do not flatten tiles, drop license files, edit data or claim scientific
validation. Add folders only for distinct purposes or demonstrated browsing need.

## 11. The recipient renamed the roots

**Request:** file a neighborhood walking-tour brochure.
The roots are `Workstreams`, `Responsibilities`, `Library`, `Timeline` and `System`.
The existing tour collection in Library owns its route map and final text.

File the brochure in the existing tour collection in `Library`. Keep the
`Responsibilities` MOC alongside `AGENTS.md` and its working `files/` folder. Preserve the recipient's root
names and existing hierarchy. Repair existing links to the moved brochure when
that repair is within the filing scope. Add a new MOC link only when separately
authorized.

## 12. A system instruction consumes a moved file

**Request:** move an approved reference sheet.
An instruction under the system root uses its old literal path. Folder Janitor
repairs authorized content-side references, then returns the exact system file
and old/new target to the designated maintainer. It cannot edit the system root.

Defer that affected move until the maintainer can preserve the dependency, while
independent work continues. If it already moved, use the authorized recovery route.
Working MOC links alone do not establish completion when a system path is broken.

## 13. A project relocation reaches instructions and code

**Request:** rename an authorized search-index project folder.
Its AGENTS.md, specification, command example, YAML input and Python Path expression
contain the old prefix. Resolve relative paths from each consumer's actual context.

| Consumer | Necessary repair | Preserve |
| --- | --- | --- |
| AGENTS.md | Active MOC target prefix | Root me.md pointer and routing |
| MOC link or embed | Target only | Label, embed marker and anchor |
| Specification and fenced command | Active path token | Requirements and options |
| YAML input | Selected path value | Other keys and scientific settings |
| Python Path expression | Literal path | Behavior and parameters |

Repair included active dependencies in the same approved operation; do not ask
again per file. Preserve historical quotations and provenance. Check syntax and
path resolution without executing the scientific workflow. Return an exact handoff
and defer the affected part when a consumer's owner is outside the authorization.

## 14. One concrete plan for a consequential operation

**Request:** reorganize a community archive's mixed image and document intake.
The inventory spans confirmed owners, an unresolved item and the held proof in
case 6. Dependencies include MOC links, an instruction pointer and a script.

Before consequential moves, show source/destination groups, affected consumers,
protected and held items, unknown ownership and a recovery plan. One approval
covers those moves and necessary repairs; routine checks do not restart approval
or require permission per file. A small move with critical dependencies also
needs a concrete impact assessment. A read-only simulation remains a proposal.

Keep unknown items unresolved and the held proof in place. Return system-root
repairs to their owner. Pause only a newly discovered consequence outside the
agreed scope and continue independent authorized work. Report filed, held, unclear
and deferred items, dependency checks and recovery location once. Completion
requires all active paths to resolve, including instructions and script literals.
