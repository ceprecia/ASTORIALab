# Research Presentation Builder

Turn established research into a usable poster or slide deck.

## Purpose

Own the requested presentation's content map, visual organization, assembly and
artifact verification. Support a plan-only request, a bounded revision, or an
editable poster/deck plus the requested export. Reuse existing scientific writing
and file-production capabilities instead of creating parallel workflows.

## Inputs

- Requested artifact, audience, purpose, speaking time for a talk, poster
  dimensions or slide aspect ratio, event requirements and delivery format.
- Existing manuscript/abstract, approved claims and figures, source data labels,
  citations, template/branding and the exact material to preserve or change.
- The chosen MOC, output owner and existing presentation file when revising.
  Read builder settings and supplied requirements before asking for them again.

## Steps

1. Identify whether the request is an outline, an existing-file revision or an
   actual file build. Reuse the current artifact; ask only for consequential
   missing format/content requirements. Leave scientific gaps explicit rather
   than inventing results, sample sizes or conclusions.
2. Map the audience takeaway and each proposed slide/panel to its supplied
   claim, evidence/figure and needed explanation. Preserve established scientific
   decisions. Use Michael Alley's message-led headline with visual evidence
   where it fits the chosen template, without forcing a new style on approved work.
3. For a talk, organize the selected content around the available time and
   audience knowledge. For a poster, make the main question, evidence and
   conclusion understandable both during a conversation and without a presenter.
   Keep figure labels, units, sample definitions and uncertainty visible.
4. Reuse approved text. When new scientific prose is needed, apply the writing
   profiles required by me.md and borrow writing-companion or the exact shared
   section writer through writing-coordinator. Pass the central claim/status,
   evidence, audience and template under its cross_system_handoff.md contract.
   Request domain fidelity review for new scientific wording, then return to
   this task's original owner. Do not reopen design or analysis merely to
   assemble a presentation.
5. Select an available artifact capability for the requested format and read its
   current instructions. Build or edit the actual editable artifact when that is
   authorized/requested; a Markdown outline is not a PowerPoint file. If source
   code must be authored, adapt 00 ASTORIA/templates/code_template.md and retain
   only needed deliverables.
6. Preserve usable figures and citations, package required assets through the
   selected artifact workflow, and export only the requested formats. Keep
   temporary renders/builds outside the vault; final files use their owning
   folder and existing navigation.
7. Open/render the produced file through the selected capability. Inspect every
   slide or the complete poster for clipping, overlap, legibility, missing
   figures, layout/order and citation placement. Confirm slide size or poster
   dimensions, figure values/labels and requested editability. Correct defects
   within scope and repeat only affected checks.
8. Return the file or bounded revision with a concise verification statement
   and remaining limitations. Distinguish source/content checks, rendered-file
   checks and any untested target-app or print behavior. Offer speaking practice
   only when relevant; do not automatically launch another team.

## Outputs

For plan-only work, return the requested content/layout plan in the current task's requested form or under the recipient's existing reporting policy. For a file build,
the editable deck/poster and requested exports in the verified owning folder.
For a revision, the requested existing artifact changes. Do not add a separate
presentation guide, duplicate MOC, source dump or version pile.

## Modular Plugin Support

Use the user's chosen available presentation/document artifact capability for
editable file creation, export and rendering, following its current instructions.
It does not own scientific decisions. Missing production/rendering capability
means reporting that exact limit and returning the useful content plan; do not
claim a file was built or visually verified. External publishing follows me.md.

## Handoffs

Use shared writing assistance for new scientific prose and Research Companion
for substantive contribution or interpretation choices; use paper-search for an explicitly needed source search, and
public-speaking-coach for rehearsal. Return to the original PhD or research
owner with its project binding intact. capture-progress and write-protocol
retain their requested recording/documentation jobs.

## Checks

The output matches the requested format and dimensions, supports each claim
with supplied evidence, preserves figures/statistics, and has been rendered and
inspected to the reported extent. The delivered file exists and is usable
through the inspected capability; no untested production state is claimed.
