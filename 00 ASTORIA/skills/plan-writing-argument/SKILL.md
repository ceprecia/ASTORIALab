# Plan Writing Argument

Make the argument inspectable before asking prose to carry it.

## Purpose

Own analytical questions, thesis formulation, section purposes, paragraph
development and the place of counterarguments. Build a useful route from the
user's current central claim to the reasoning each section needs. This is a
writing plan, not an independent decision about scientific interpretation.

## Inputs

Read the [writing contract](../writing-coordinator/references/writing_contract.md).
Load the current brief, relevant MOC sections and any recipient-supplied writing guidance through that contract. Use the current text, audience, writing task,
selected structure, evidence boundary and central claim with its status.
Distinguish an adopted claim from a proposed claim, question or missing choice.

## Steps

1. Restate the actual reader question. Separate the broad topic from the
   question the document can answer. Identify the evidence available to answer
   it and the practical or intellectual consequence of an answer.
2. Recover the user's central claim exactly. If it is provisional, keep that
   status visible. If it is absent, propose only evidence-supported alternatives
   or a question-led outline; do not silently pick a scientific conclusion.
3. Decompose the claim into necessary reasoning moves. For each section state
   its job, the subordinate claim or information it supplies, and its link to
   the whole argument. Follow the selected application or document structure.
4. Choose an outline appropriate to the section's function and selected document structure. Make consequential claims, support and inferential gaps reviewable without prescribing a fixed paragraph schema. Operational instructions may need an action sequence; a descriptive passage may need clear entities and relationships. Use a named paragraph framework only when the recipient selects it.
5. Place serious counterarguments where they bear on a premise or inference.
   Identify what evidence would weaken, qualify or overturn the intended claim.
   Do not add an objection solely to simulate balance.
6. Identify dependencies: which definition, observation or reasoning step must
   precede another. Combine redundant moves and expose leaps that require an
   unsupported premise.
7. Reverse-outline an existing draft if supplied. Compare its actual topic
   sentences and paragraph jobs with the intended argument; preserve useful
   material and specify the minimum reordering or missing content.
8. Return a usable bounded outline. Put missing evidence and unresolved
   decisions beside the affected move rather than creating a separate
   exhaustive planning apparatus.

## Outputs

A concise claim-to-section map and, when useful, a passage-purpose outline in the recipient-selected form. A named paragraph framework is optional. Distinguish current decisions, proposed organization and open
scientific choices. Save the result only when requested. Use the existing project context rather than a new hub.

## Boundaries

- Do not make a provisional central claim appear settled through polished wording.
- A citation list, analysis order or generic funnel is not an argument.
- Do not demand a new roadmap or approval when the current task and argument
  are already clear. Continue supported work while a consequential choice is open.
- Apply writing profiles only when producing the kind of prose specified in
  `me.md`; planning itself does not activate them.

## Handoffs

Return to writing-coordinator or the invoking owner. Send evidence gaps to
develop-writing-evidence; send the bounded outline to the matching section
writer. Scientific interpretation returns through
[cross-system handoffs](../writing-coordinator/references/cross_system_handoff.md)
to the existing domain lead. When the recipient selects CERL, check-writing-cerl can review that named framework. Otherwise obtain reasoning review appropriate to the document's purpose without imposing a paragraph method.

## Checks

- Every section has a distinct purpose and a visible relationship to the whole.
- Each proposed premise is sourced, user-supplied or explicitly unresolved.
- The outline remains useful if citation names are removed.
- The user's selected structure, exact terms and claim status survive.
