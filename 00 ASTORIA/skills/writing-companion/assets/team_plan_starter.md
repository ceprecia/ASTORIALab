# Starter team plan for complex project writing

Use this starter when Writing Companion is asked to propose a team for complex project writing. Curate the assignments, skills and timing for the actual task. The roster is a proposal, not a dispatched team.

## Curate the plan

- Use the current project, document, requested outcome, evidence and decisions. Keep provisional claims and missing inputs visible.
- Begin with at least two relevant specialist skill chats outside writing assistance. Give them distinct bounded domain jobs. They can belong to the same domain; two different domains are not required. Companions, coordinators, writers and artifact-formatting helpers do not count toward this minimum.
- Discover exact installed skills through the current domain owner and its relevant catalog. Reuse suitable authorized specialists. If two relevant owners cannot be verified, identify the capability gap instead of inventing a skill or filling the slot with an irrelevant worker.
- Useful domain pairings include application requirements and scientific critique for a research proposal; design details and test-evidence interpretation for an engineering report; or curriculum accuracy and assessment design for teaching material. Select the actual skill owners for the task rather than treating these examples as a fixed roster.
- Follow the writing-role tables below as the starting structure. Curate the writing roles and section scopes; add several workers with the same skill when their assignments differ. The two-domain-chat minimum remains part of this starter.
- Use the single shared naming registry at `00 ASTORIA/skills/research-coordinator/references/team_naming.md`. Verify the current project and existing chats before allocating titles or numbers. Coordinators remain inside the lead chat; borrowed Writing Companion stays with the original session owner.
- Show which assignments can run in parallel, which need earlier returns, and which are for later. Each writer receives the shared scientific or technical frame, exact section purpose, source locations and unresolved decisions. Keep one editor for the canonical document.
- An explicit plan request skips the preliminary offer. A plan alone does not launch chats. Carry existing execution authorization forward without asking again; editing this template or its skill does not launch a team. Follow the coordinator's existing dedicated-chat and internal-worker rules.

## Plan information and fallback layout

Build the plan from the project and goal, evidence and decisions, session owner and return point, and concrete assignments and dependencies. Present it in the form selected for the task, then under the applicable verified reporting policy. Show the requested detail and retain the required pre-dispatch information. When neither specifies a form, use the layout below.

**Project and writing goal:** [project/document; requested deliverable; audience]

**Starting material and decisions:** [current artifact; supported evidence; selected and provisional choices; important missing inputs]

**Coordination:** [current session owner and return point; Writing Companion and internal coordinator; proposed or verified chat destination]

Construct the domain-first roster and honor the actual dispatch dependencies. Use actual assignments and identify gaps explicitly. The fallback layout displays domain specialists first. In that layout, replace its bracketed slots with the assignments or gaps.

### Writing preparation

| Fixed role | Skill | Starter assignment | Timing or dependency |
| --- | --- | --- | --- |
| Organizer | `organize-writing-project` | Map sections to existing drafts, readiness, missing inputs and next actions in the existing project context. | Start for an application or multipart document. |
| Argument Planner | `plan-writing-argument` | Connect the controlling question and claim to section purposes and paragraph reasoning; preserve provisional choices. | Start from the current draft or brief. |
| Evidence Specialist | `develop-writing-evidence` | Build source-to-claim reasoning for bounded claims; return literature or domain gaps to their owners. | Begin with supplied sources; incorporate domain returns. |
| Bibliographer | `verify-writing-citations` | Verify citation identities and exact support for claim–citation pairs. | Existing citations can be checked while framing develops. |
| Structure Keeper | `keep-writing-structure` | Apply the selected template, section functions and verified requirements. | Use the relevant domain requirements return. |

### Content writers

| Fixed role and focus | Skill | Starter assignment | Timing or dependency |
| --- | --- | --- | --- |
| Section Writer - [exact custom section] | `write-section` | Draft a named application, training, teaching or other custom section from its purpose and evidence. | Use a bounded brief; label unresolved choices. |
| Introduction Writer - [rationale or opening] | `write-introduction` | Connect the supported problem and gap to the question, rationale and contribution. | Use the current argument and source support. |
| Methods Writer - [procedure, Approach or aim] | `write-methods` | Describe proposed or performed procedures and analyses from the domain owners' verified returns. | Preserve the actual evidence and execution state. |
| [Other content-specific writer] | [verified writing skill] | [exact section, output and supporting material] | Add only for a section the document needs. |

Select the writers that fit the document. A proposal need not have journal-style Results, Discussion or Conclusion sections. Supported outlines and provisional passages can proceed while consequential domain choices remain open. Obtain technical detail through the existing cross-system handoff; use Domain Translator (`translate-specialist-methods`) when intricate specialist records need translation.

Add Reporting Reviewer (`check-research-reporting`) only when a current reporting-guideline check is relevant. Keep substance, reasoning, citation, structure and technical findings distinct.
