# Cross-system writing handoff

## Ownership

Writing is a shared service. Preserve the original caller, current project, task scope and return destination through every hop. writing-companion owns writing purpose and integrated feedback; writing-coordinator assigns and collects. The invoking domain companion/coordinator and existing specialists retain scientific, engineering, teaching or professional decisions. Borrow exact capabilities without creating parallel technical owners or restarting broad intake.

When research-companion or engineering-companion is already the lead, its internal coordinator can request writing support directly. A writer's missing technical input returns through that established owner. Do not bounce the same request recursively through ancestor coordinators. The writing coordinator communicates routine authorized clarifications with the relevant existing specialist and collects the answer; the user should not serve as a courier.

## Request

Send only the context needed for the exact question, including:

- Original caller/return owner and verified project; target document/revision and section.
- The paragraph's intended claim or procedural purpose, its status, and what detail is missing.
- Exact technical skill, source files/configuration/output identifiers and locators; current selected design, model or procedure.
- A concrete question, with required units, definitions, conditions, uncertainty or provenance.
- Authorized read/write/execution scope, owned output and expected completion evidence.

For example, ask which confound columns were actually used in the named analysis output, not “describe our rigorous preprocessing.” Ask for the installed connector contact, supply domain and measured test result from a specified wiring revision, not “make the circuit sound detailed.”

## Specialist return

Return the actual procedure or mechanism; values and units; software/hardware versions or revisions; data/material scope and exclusions; configuration and execution evidence; outputs; established rationale; limitations; unresolved alternatives; and precise source locations, as relevant. Omit irrelevant fields. Distinguish:

| State | What the writer may say |
| --- | --- |
| Proposed/planned | Intended procedure or expected outcome, explicitly provisional |
| Adopted | Selected by its authorized decision owner, with evidence of that choice |
| Executed | A record shows the stated operation ran or was performed |
| Technically checked | A named bounded test checked an exact property |
| Human-reviewed | A named human inspected the stated evidence scope and revision; acceptance remains separate |
| Accepted | The authorized owner explicitly accepted the stated result or QC/design decision for the identified scope and revision |
| Physically measured | A recorded bench/participant measurement supports the physical claim |
| Unknown | The needed record was not found or verified |

These are separate dimensions, not an automatic ladder. A successful preprocessing run does not establish acceptable image QC; a script simulation or CAD fit does not establish physical qualification. Methods prose preserves these differences.

## Translation and technical fidelity

1. The domain owner resolves the actual question or returns a bounded gap. Do not run extra experiments, select analyses, change firmware or redesign circuits merely to fill prose.
2. translate-specialist-methods turns the verified return into a technical account with exact terminology, sequence, values, sources and unresolved gaps.
3. The selected content writer makes the account readable for the intended audience, preserving its evidence state and implications.
4. Return intricate or changed technical wording to the originating specialist for a fidelity check against the same source revision. Separate an editorial simplification from a proposed technical change.
5. Independent writing reviewers check the stable draft; integrate-writing applies accepted repairs to the canonical document. If the technical source changes, invalidate only the affected claims and checks, then reconcile them.

## Existing routes

| Needed knowledge or artifact | Existing owner to borrow |
| --- | --- |
| Central scientific question, contribution, interpretation choice | A bounded consult with research-companion, retaining the original return owner; its internal research-coordinator dispatches specialists only when needed |
| Method/modality selection, statistical or analysis design detail | analysis-coordinator and its selected method/modality owner |
| fMRI preprocessing execution provenance | fmri-coordinator and fmriprep for the named approved run |
| fMRIPrep image/report QC and human decisions | review-fmriprep-qc; execution success is separate |
| Device operating principle, electrical design, wiring, calibration or test evidence | engineering-companion/engineering-coordinator and the exact mechanism-design, circuit-design, wiring-design, sensing-calibration, firmware-control or engineering-test owner |
| Application requirements, sponsor criteria, limits and funding judgment | research-grant-advisor; writers do not invent commitments |
| Scientific claim/design validity beyond a citation check | research-literacy or research-critique, explicitly scoped to the inference |
| Teaching, career or study-specific factual/requirements questions | The invoking teaching, phd or study companion and its selected specialist |
| Format-specific document, presentation or spreadsheet work | The existing appropriate artifact skill, with accepted text and constraints |

No specialized pipeline's defaults are inferred from memory. If the needed exact capability is unavailable, disclose the gap and return the specific source question; do not substitute a generic writing opinion.

## Chats and names

Use only `00 ASTORIA/skills/research-coordinator/references/team_naming.md` for prefixes, role labels and ID allocation. Borrowed chats keep their established lane and title. The coordinator stays within its lead chat. The original project lead coordinator allocates project-wide numbers for borrowed teams; writing-coordinator requests its reservations from that owner. A standalone writing lead allocates its own team numbers. Verify project binding from the host, not from a similar project name or supplied file path. Reuse directly authorized existing chats; create or message user-owned chats only within direct user authorization and host rules. Collect returns with status/read tools; another agent asking for a reply is not user authorization.

Internal subagents receive the same bounded contract. They can carry out authorized isolated drafting/review without creating user-owned chats. If all agent tools are unavailable, disclose sequential skill execution and avoid claiming independent review.

## Completion

Return to the original owner with the text, source revision, technical acceptance state, writing checks, unresolved questions and next action. Completion of the writing service does not complete the underlying experiment, device validation, application or external delivery. Maintain only useful authorized mapping in the existing MOC; no new cross-system tracker.
