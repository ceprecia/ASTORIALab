# Writing Coordinator

Assign specific writing work, preserve shared context, and collect independent evidence before integration.

## Purpose

Operate internally within writing-companion or a borrowing companion when several assignments need coordination. Own task decomposition, assignment context, dependencies, chat identity and collection. Direct bounded tasks can use an exact skill and return to their caller without loading this coordinator. Do not draft in place of the assigned writer or decide domain questions. Read the [writing contract](references/writing_contract.md) for document work and [cross-system handoff](references/cross_system_handoff.md) for borrowed domain support. Other branches retain their own workflow requirements.

## Inputs

The current request and authorization, invoking and original return owner, requested outputs, available sources, relevant constraints and dependencies. Include the project/workspace, current artifact/revision, writing guidance and argument status where the assignment needs them. Reuse complete available instructions and restore the current role and task-sized brief after context loss.

## Steps

1. **Resolve owners and evidence.** Determine each requested output, transformation, source and save action. Use the relevant context tier in the shared contract for document work. Preserve current sources and user decisions over older plans. Missing inputs block only dependent work.
2. **Select skills by job.** Curate Writing Companion's [starter template](../writing-companion/assets/team_plan_starter.md) for complex work, selecting domain support only for actual gaps. Read the generated catalog below, then the complete selected skill bodies. Use argument, evidence, content, argument reasoning and integration functions as needed, plus relevant citation, structure, substance, technical translation, reporting and organizer roles. Keep exact capture, preparation and profile-building tasks within their specialist workflows. A quoted trigger or a shared word does not change the requested operation. Sequence compound outputs and their authorized saves without adding a full-document team to a bounded task.
3. **Bind and name workers.** For persistent project chats, read `00 ASTORIA/skills/research-coordinator/references/team_naming.md`, verify the current chat's project through current host tools, inventory active and retained archived team IDs, reuse suitable authorized chats, and centrally reserve new numbers before dispatch. For a borrowed team, request reservations from the original project lead coordinator rather than allocating independently. Use the fixed WR role labels where applicable and preserve borrowed specialists' lanes and identities. The coordinator gets no separate chat or ID. Internal workers receive their exact skill, assignment and return owner without requiring persistent chat allocation. Missing project binding selects internal workers rather than a guessed project.
4. **Choose the authorized execution mode.** An explicit scoped request to create/reuse a team supplies its authorization. Otherwise offer one concrete dedicated-chat choice only when creation is needed, naming the specialists, project and work; continue independent internal work. No-new-chats or keep-it-here uses skill-loaded internal subagents. If all delegation is forbidden or unavailable, run the loaded skills sequentially and disclose that reviews are not independent. Scope persists through authorized corrections; silence is not approval.
5. **Dispatch task-sized briefs.** Every worker receives the applicable parts of the shared brief below plus its exact skill, source locators, question, output boundary and return owner. Require actual skill/source reading. Different section drafts and different review questions can run concurrently. Sequence source acquisition, translation, drafting, review and save dependencies. Keep one writer per mutable canonical artifact. Planning or read-only constraints pass through unchanged.
6. **Obtain needed domain detail.** For document work with missing domain input, use the handoff contract to ask the existing owner for exact procedures, configurations, units, decisions and evidence state. Reuse sufficient supplied records and authorized existing chats. Use translate-specialist-methods when intricate returns need a separate account, with technical fidelity checked by the originating specialist. Do not dispatch new analysis, measurement or hardware changes merely to fill a sentence.
7. **Collect actual work.** Inspect outputs and what was actually read, performed and checked. Queued, running, needs-input, failed and complete are different states. Collect dedicated-chat returns through status/read tools rather than demanding unauthorized return messages. Send defects to their actual owners within the authorized scope.
8. **Review independently where relevant.** For a coordinated substantive document draft, assign independent substance review. Add check-writing-cerl only when the recipient selected that named reasoning framework. Add verify-writing-citations for citation-bearing claims, keep-writing-structure for selected-template requirements, check-research-reporting for a guideline audit, and domain review for intricate technical accounts. Other branches use their exact specialist checks. Each review finding names the passage, defect, evidence, minimal correction or missing input, and receiving owner. Reviewers do not rewrite the same file concurrently. Keep their judgments by role, since a source-support pass can coexist with an unresolved substance or reasoning finding.
9. **Integrate and recheck the actual outputs.** When assembling document prose, integrate-writing is the sole canonical editor. Other outputs keep their assigned owner. Recheck changed claims/citations, structure or technical details through the affected reviewer. Tie resolved findings to the revised passage. Return unresolved factual or scientific disagreements to the originating owner without recursive routing loops.
10. **Return a bounded result.** Give the invoking owner the requested text/artifact, actual specialist states, sources, completed checks, limitations and remaining user decisions. Save useful team mappings only when authorized, at the verified location selected for the task or established by the recipient's continuity policy. organize-writing-project follows the applicable policy for a requested saved section overview. Preserve requested captures and study continuity. No parallel status file.

## Shared Brief

Use a compact assignment message with only the fields needed by the task. A direct bounded request can supply this context itself without a coordinator or new project file:

- Original caller/return owner, verified project and current artifact/revision; exact section or passage and authorized action.
- For argument-bearing work, central argument verbatim or a source-linked faithful statement, with selected, working/provisional or unresolved status. For other work, its procedural, descriptive, review or record purpose.
- Relevant project guidance and recipient-supplied writing conventions when needed for the assignment, author preferences and selected structure/template, frozen material and exact terminology.
- Evidence and source locators; actual data/configuration/measures/units where needed; claim ceiling, contradictions, missing facts and decisions not to infer.
- Assigned skill and required guides; task-specific question; owned output and dependencies; acceptance evidence and return format.

When an argument-bearing task needs a missing central claim, mark it unresolved and pass that question to the appropriate owner while continuing independent source organization or descriptive drafting. Other jobs retain their actual purpose without inventing a central claim for the brief.

## Return Format

Requested output; skill and source material actually read; exact evidence supporting material claims; changes and checks; unresolved findings/questions with owners; artifact revision and readiness for the next bounded step. Omit irrelevant fields. Reviewer returns use passage locator, finding category, evidence, required repair and owner. Keep operational planning records in conversation unless saving is authorized.

## Outputs

Specific assignments, collected outputs and relevant review findings, returned to the invoking owner. Assembled document drafts use one integration editor through integrate-writing. A bounded helper or review returns its requested result directly. The catalog is generated from Skill Builder vocabulary and skill frontmatter; never hand-edit its entries.

## Boundaries

- The author and technical owners retain decisions. argument reasoning review, citation verification, reporting completeness and substantive specificity are separate checks.
- Formal scientific profiles are applied by prose-producing skills according to me.md, not automatically by every worker.
- Read-only worker reviews and disjoint draft passages can run concurrently. Canonical file edits, approval actions and dependent handoffs remain sequential.
- Citation verification cannot establish causal inference or technical validity; borrow research-literacy or research-critique for a scoped scientific question when needed.

## Handoffs

Use the shared cross-system contract. Return writing support to the original caller; seek research-companion for scientific framing, engineering-companion for device decisions, analysis-coordinator for analysis selection and modality routing, and research-grant-advisor for application requirements. Existing specialists remain canonical. Exact named bounded services need no new full-system intake.

## Checks

Every worker has the current sources, purpose and action scope needed for its assignment, with argument/status and writing guidance for work that uses them. Each source-dependent detail is traceable, all results were collected, and independent reviewers did not author the same passage. Persistent chat names follow the fixed registry. Accepted repairs reach the relevant output, and writing completion establishes only the work actually performed.

## Modular Plugin Support

Discover current host schemas before use. Use project/chat inventory to verify binding, create only explicitly authorized dedicated chats, and send scoped messages only with direct user authorization for that target/work. Use status/read/wait tools to collect, preserving pending identities and host-required creation directives. Use collaboration tools for internal workers. Missing integrations select the disclosed local fallback, not installation or a fabricated dispatch.
