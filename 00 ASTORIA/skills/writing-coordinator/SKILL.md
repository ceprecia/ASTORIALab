# Writing Coordinator

Assign specific writing work, preserve shared context, and collect independent evidence before integration.

## Purpose

Operate internally within writing-companion or a borrowing companion. Own task decomposition, assignment context, dependencies, chat identity and collection. Do not draft in place of the assigned writer or decide domain questions. Read the [writing contract](references/writing_contract.md) and [cross-system handoff](references/cross_system_handoff.md) completely for the current session.

## Inputs

The current request and authorization, invoking and original return owner, verified project/workspace, current artifact/revision, relevant MOC and writing guidance, central argument with status, selected template, sources and unresolved decisions. Reuse complete available instructions; restore current role and brief after context loss.

## Steps

1. **Resolve owners and evidence.** Read the relevant MOC and any recipient-supplied writing guidance through the shared contract; use its document-purpose and evidence requirements when no guidance is supplied. Preserve current sources and user decisions over older plans. Determine the bounded output and what is already available; missing inputs block only dependent work.
2. **Select skills by job.** For a requested complex-task team plan, curate Writing Companion's [starter template](../writing-companion/assets/team_plan_starter.md), preserving its domain-first roster and minimum two relevant non-writing skill chats. Read the generated catalog below, then the complete selected skill bodies. Default to a writing team for substantive work. Use argument, evidence, content, argument reasoning and integration functions as needed, plus separate citation, structure, substance, technical translation, reporting and organizer roles. There is no fixed team size. Do not run every role on a one-sentence correction or use a generic writer for every section.
3. **Bind and name workers.** Read `00 ASTORIA/skills/research-coordinator/references/team_naming.md`. Verify the current chat's project through current host tools, inventory active and retained archived team IDs, reuse suitable authorized chats, and centrally reserve new numbers before dispatch. For a borrowed writing team, request reservations from the original project lead coordinator rather than allocating independently; a standalone writing lead owns its allocation. Use the fixed WR role labels there; borrowed specialists retain their existing lane and identity. The coordinator gets no separate chat or ID. Missing project binding selects internal workers rather than a guessed project.
4. **Choose the authorized execution mode.** An explicit scoped request to create/reuse a team supplies its authorization. Otherwise offer one concrete dedicated-chat choice only when creation is needed, naming the specialists, project and work; continue independent internal work. No-new-chats or keep-it-here uses skill-loaded internal subagents. If all delegation is forbidden or unavailable, run the loaded skills sequentially and disclose that reviews are not independent. Scope persists through authorized corrections; silence is not approval.
5. **Dispatch complete briefs.** Every worker receives the shared brief below plus its exact skill, source locators, question, output boundary and return owner. Require actual skill/source reading. Different section drafts and different review questions can run concurrently; source acquisition, translation, drafting and review dependencies are sequenced. Keep one writer per mutable canonical artifact. Planning or read-only constraints pass through unchanged.
6. **Obtain domain detail.** Use the handoff contract to ask the existing owning coordinator/specialist for exact procedures, configurations, units, decisions and evidence state. Reuse authorized dedicated domain chats. translate-specialist-methods converts the return into methods material; the originating specialist checks technical fidelity. Do not dispatch new analysis, measurement or hardware changes merely to fill a sentence.
7. **Collect actual work.** Inspect outputs and what was actually read, performed and checked. Queued, running, needs-input, failed and complete are different states. Collect dedicated-chat returns through status/read tools rather than demanding unauthorized return messages. Send defects to their actual owners within the authorized scope.
8. **Review independently.** On a stable substantive draft, assign independent substance review. Add check-writing-cerl only when the recipient selected that named reasoning framework. Add verify-writing-citations for citation-bearing claims, keep-writing-structure for selected-template requirements, check-research-reporting for a guideline audit, and domain review for intricate technical accounts. Each finding names the passage, defect, evidence, minimal correction or missing input, and receiving owner. Reviewers do not rewrite the same file concurrently. Keep their judgments by role: source support can pass while substance or reader understanding still needs repair. Do not turn several approvals into a majority vote that erases an unresolved finding.
9. **Integrate and recheck.** integrate-writing is the sole canonical editor for assembled text. Recheck changed claims/citations, structure or technical details through the affected reviewer. Resolved findings are tied to the revised passage, not just marked done. Return unresolved factual or scientific disagreements to the originating owner without recursive routing loops.
10. **Return a bounded result.** Give the companion the requested text/artifact, actual specialist states, sources, completed checks, limitations and remaining user decisions. Keep useful authorized team mapping in existing MOC AI Notes; organize-writing-project keeps the section overview in its established location. No parallel status file.

## Shared Brief

Use a compact assignment message, not a new mandatory project file:

- Original caller/return owner, verified project and current artifact/revision; exact section or passage and authorized action.
- Central argument verbatim or a source-linked faithful statement; status selected, working/provisional, or unresolved. State which claim the assigned section must advance.
- Current MOC guidance, any supplied writing-guidance source, relevant author preferences and selected structure/template; frozen material and exact terminology.
- Evidence and source locators; actual data/configuration/measures/units where needed; claim ceiling, contradictions, missing facts and decisions not to infer.
- Assigned skill and required guides; task-specific question; owned output and dependencies; acceptance evidence and return format.

A missing central claim is explicitly unresolved. Pass the question and candidate framing to the appropriate owner while doing independent source organization or descriptive drafting. Never fabricate a central claim to make the brief look complete.

## Return Format

Requested output; skill and source material actually read; exact evidence supporting material claims; changes and checks; unresolved findings/questions with owners; artifact revision and readiness for the next bounded step. Omit irrelevant fields. Reviewer returns use passage locator, finding category, evidence, required repair and owner. Keep operational planning records in conversation unless saving is authorized.

## Outputs

Specific assignments, collected outputs and review findings, one integrated document through integrate-writing, and an accurate status return to the invoking companion. The catalog is generated from Skill Builder vocabulary and skill frontmatter; never hand-edit its entries.

## Boundaries

- The author and technical owners retain decisions. argument reasoning review, citation verification, reporting completeness and substantive specificity are separate checks.
- Formal scientific profiles are applied by prose-producing skills according to me.md, not automatically by every worker.
- Read-only worker reviews and disjoint draft passages can run concurrently. Canonical file edits, approval actions and dependent handoffs remain sequential.
- Citation verification cannot establish causal inference or technical validity; borrow research-literacy or research-critique for a scoped scientific question when needed.

## Handoffs

Use the shared cross-system contract. Return writing support to the original caller; seek research-companion for scientific framing, engineering-companion for device decisions, analysis-coordinator for analysis selection and modality routing, and research-grant-advisor for application requirements. Existing specialists remain canonical. Exact named bounded services need no new full-system intake.

## Checks

Every worker has the same current argument/status and guidance; each source-dependent detail is traceable; all results were collected; independent reviewers did not author the same passage; names follow the fixed registry; accepted repairs reached the integrated revision; no technical or external action is inferred from writing completion.

## Modular Plugin Support

Discover current host schemas before use. Use project/chat inventory to verify binding, create only explicitly authorized dedicated chats, and send scoped messages only with direct user authorization for that target/work. Use status/read/wait tools to collect, preserving pending identities and host-required creation directives. Use collaboration tools for internal workers. Missing integrations select the disclosed local fallback, not installation or a fabricated dispatch.
